# 知识迭代（K-Loop）

> 完整方法论见 `{{VAULT_PATH}}/_系统/知识迭代协议.md`（先读它）。本 Skill 是它的可执行化。

## 核心哲学
**读过 ≠ 理解，记住 ≠ 会用。** 理解的唯一证明 = 关书后能从零重建。知识 = 模型，迭代 = 训练 epoch。

## 触发后立即执行

### 0. 定位目标概念
- 如果用户给了 `[[概念名]]`，概念文件夹应在 `{{VAULT_PATH}}/10-知识原子/<概念名>/`
- 若找不到，先检查 `30-已掌握/` 和 `00-收件箱/`
- 概念四件套：`<概念名>.md`（主笔记，以概念名命名）/ `重建稿.md` / `压缩版.md` / `教授稿.md`
- **必须**先读 `<概念名>.md`（主笔记）和 `{{VAULT_PATH}}/_系统/知识迭代协议.md`

### 1. 一轮 K-Loop 五步

**1️⃣ 试（前向）** — 让用户做一次真实尝试：
- 提问：「上一轮之后，你动手试过它吗？做了什么？」（做题/写码/讲解/项目）
- 若用户没尝试 → **停止**，提醒「没有尝试不算迭代」，请先去用一下再回来。

**2️⃣ 差（损失）** — 收集现实反馈：
- 提问：「哪里卡住 / 哪里错了 / 和预期不符？」引导产出**一条**明确落差：「我本以为 X，实际发现 Y」。
- 用户给不出落差 → 帮他从「试」的经历里挖掘。

**3️⃣ 因（反向归因）** — AI 核心工作，做深层分析：
- 把落差**追溯到笔记具体位置**：哪个假设错了？哪个原子没拆透？哪条推导链断了？
- 在主笔记 `<概念名>.md` 的「落差记录」顶部追加一条（带版本号与日期），含试/差/因/改 四行。
- 归因必须**具体**，禁止写「还没理解」这类空话。

**4️⃣ 改（更新）** — 修正笔记：
- 修改主笔记 `<概念名>.md`：纠错/补全/重拆/压缩「一句话直觉」。
- frontmatter：`版本` +1，`迭代次数` +1，`落差值` = 本次落差数，`上次迭代` = 今天。
- 在 `{{VAULT_PATH}}/20-迭代日志/` 写 `<概念名>-YYYY-MM-DD.md`（用 [[02-迭代日志模板]] 结构，五行全填）。
- 若本轮发现需要重新拆解 → 更新「第一性原理拆解」章节。

**5️⃣ 验（重建测试）** — 关书验证：
- 打开 `重建稿.md`，请用户**关书**从零重写（或 AI 出题考关键机制）。
- 禁止让用户参考资料；参考了 = 本轮无效。
- 结果 ✅ → 记入主笔记 `<概念名>.md` 重建记录表；连续 2 次 ✅ → 检查收敛。
- 结果 ❌ → 把卡壳点写回「落差记录」，回到第 3️⃣ 步重新归因。

### 2. 收敛检查与晋升
全部满足 → 建议晋升：
- 重建稿连续 2 次 ✅ 且零参考
- 压缩版一页纸准确无损
- 教授稿新手能复述

晋升动作（征得用户同意后执行）：
1. 主笔记 `<概念名>.md` 状态改 `已掌握`
2. 把整个 `<概念名>\` 文件夹从 `10-知识原子\` 移到 `30-已掌握\`
3. 提示用户在 [[仪表盘]] 登记

### 3. 红线（不可违反）
- 不背结论，必须能推（第一性原理）
- 每轮必须有一条落差，否则不算迭代
- 重建必须关书
- 压缩不得失真
- 未过验证不得标「已掌握」

### 4. 违规与刹车
- 用户说 **「违规」**：本轮跳了步骤 → 回退缺口，重做该步。
- 用户说 **「刹车」**：连续 3 轮落差不降 → 停止打补丁，回到第一性原理重新拆解，必要时降级回收件箱。
- 修改前若涉及文件移动/改写，先向用户确认动作清单。

### 5. 收尾汇报
一轮结束后，输出摘要：
- 版本：vX → vY
- 落差：一句话
- 归因：错在哪
- 重建：✅/❌
- 下一步建议：继续迭代 / 晋升 / 重新拆解
