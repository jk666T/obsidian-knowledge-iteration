# 整理收件箱（Inbox → Loop）

> 前置：先读 `{{VAULT_PATH}}/_系统/知识迭代协议.md` 了解 K-Loop 与「四件套」结构。
> 本 Skill 是知识迭代系统的**入口**：把散落在收件箱的碎片送进循环。

## 0. 扫描与判定

1. 列出 `{{VAULT_PATH}}/00-收件箱/` 下的全部文件。
2. **若为空** → 报告「收件箱已清空」，提示打开 [[仪表盘]] 看迭代队列，结束。
3. **若非空** → 全部列出，进入逐条分类。

## 1. 逐条分类（核心工作）

对每条笔记**先读内容**，再判定归属：

| 分类 | 判定标准 | 动作 |
| :-- | :-- | :-- |
| 🆕 新概念 | 内容完整、自成一体、库中无对应原子 | 建 `10-知识原子/<概念>/` 四件套 |
| 🔗 归并 | 是已有原子的补充 / 细节 / 反例 | 并入对应原子的 `<概念>.md` 对应章节 |
| ❓ 疑问 | 是一个「问题」而非「知识」 | 移入 `疑问/`（保留原文） |
| 🗑 无用 | 重复、失效、纯草稿 | 建议删除（**需用户确认**） |
| 🤔 拿不准 | 无法判断 | 问用户，绝不擅自归类 |

**铁律：**
- **归并优先于新建。** 先扫 `10-知识原子/` 与 `30-已掌握/` 确认没有对应原子，才允许建新。
- 新概念必须能撑起四件套（本尊 / 重建稿 / 压缩版 / 教授稿）。撑不起来的先归并，或留在收件箱标注「待拆解」。
- 分类结果是**建议**。执行前一次性列出「待执行清单」征求用户确认，不要逐条反复问。

## 2. 执行（用户确认后）

- **建新原子**：按 `_系统/模板/01-原子笔记模板.md` 创建 `<概念>/<概念>.md` + `重建稿.md` + `压缩版.md` + `教授稿.md`。把收件箱原文吸收进「第一性原理拆解」或「我的理解」；frontmatter 填 `状态: 迭代中`、`版本: v1`、`迭代次数: 0`、`上次迭代: 今天`。
- **归并**：把原文内容追加进目标原子的对应章节，在该章节标注来源：`📥 收件箱归并 · <日期>`。
- **移走 / 删除**：疑问移入 `疑问/`；无用删除前**再次确认**。
- 每条处理完，**删除或移走收件箱原文件**（内容已进原子或疑问区，避免下次重复处理）。

## 3. 收尾

- 更新 [[仪表盘]] 的**纯 Markdown 兜底表格**（收件箱 / 迭代中队列 / 最近迭代）。
- 汇报：
  - 几条入环 / 几条归并 / 几条移走 / 几条删除
  - 新建的原子建议立刻跑第一轮：**「迭代 [[概念名]]」**
  - 若收件箱仍留下「待拆解」内容，明确标注出来
