# 周报（Weekly Review）

> **定位**：只给自己看的自我复盘。允许写卡点、拖延、没做完的事，不粉饰、不写成汇报体。
> **原则**：数据用表格，洞察用短段；每条结论必须能追溯到具体笔记（`[[wikilink]]`）；没有数据就写「无」，**绝不编造**。

---

## 0. 前置

1. 读 `_系统/周报/_周报配置.md`：周期、学习计划、项目排除项、停滞口径。若不存在，按文末「配置模板」创建并告知用户；若 `_系统/周报/` 目录不存在，一并创建。
2. 需要理解「落差值 / 刹车」时，读 `_系统/知识迭代协议.md` 对应小节。
3. 确定周期与文件名：

```bash
week=$(date +%G-W%V)
monday=$(date -d "$(date +%F) -$(( $(date +%u) - 1 )) days" +%F)
sunday=$(date -d "$(date +%F) +$(( 7 - $(date +%u) )) days" +%F)
# 结果示例：week=2026-W44 monday=2026-10-26 sunday=2026-11-01
```

- 目标文件：`_系统/周报/$week.md`
- 用户说「补上周周报」：把 `date +%F` 换成上一个 ISO 周的任意一天（如 `date -d "last monday" +%F`）重算；或直接问用户周次。
- 用户指定周期（如「按上周一到今天」）：以用户为准，文件名仍用该周期的 ISO 周号。

4. **幂等检查**：目标文件已存在时，先读全文，列出：
   - 将保留的段落（含 `<!-- 手动 -->` 标记或用户手写内容）
   - 将重算覆盖的段落
   征求确认后再写。默认**保留手动段落，只重算自动段落**。

## 1. 数据采集

| 数据 | 来源 | 取法 |
| :-- | :-- | :-- |
| 收件箱处理流水 | `_系统/仪表盘.md`「📥 收件箱（待整理）」表 | 读表，取日期落在本周的行，**按自然语言归纳**新建/归并/删除条数；不要机械正则 |
| 迭代记录 | 仪表盘「🕒 最近迭代记录」表 + `20-迭代日志/**/*.md` | 日志 frontmatter 有 `类型 / 概念 / 日期 / 版本`；筛 `日期` 在本周 |
| 原子状态 | `10-知识原子/**/<概念>.md` frontmatter | 用 Grep 提取 `类型: 原子笔记` 的 `状态 / 版本 / 迭代次数 / 落差值 / 上次迭代 / 大类 / 领域`；**不要逐篇通读全文** |
| 已掌握 | `30-已掌握/**/*.md` frontmatter | 取 `上次迭代` / 晋升日期在本周的 |
| 收件箱存量 | `00-收件箱/` | `find "{{VAULT_PATH}}/00-收件箱" -maxdepth 1 -type f \| wc -l` |
| 疑问区 | `疑问/*.md` | 列文件 + 读首段；按文件修改时间算挂起天数 |
| 项目 | `_系统/项目交接文档/*.md` | 读 frontmatter 或首段「最近更新 / 状态」+「待办」；用文件 mtime 或 `git -C <dir> log --since=<monday>` 判断本周是否有动作（无此目录则跳过该项目，写「无」） |
| 学习计划 | `_周报配置.md` 里的来源文件 | 统计 `- [x]` / `- [ ]`；与上一份周报第 5 节对比 |
| 补漏 | 全库文件 mtime | `find <目录> -type f -newermt "$monday" ! -newermt "$(date -d "$sunday +1 day" +%F)"`，只用于发现仪表盘漏记的活动；报告里注明「估算」 |

**采集纪律**：
- 仪表盘是手写流水，允许口语化；以它为主，文件时间为辅。
- 同一事件在仪表盘和迭代日志都出现时，只计一次。
- 无法确认归属的内容，标注「未归类」，不要硬塞进统计。
- **仪表盘某张表为空或整张表不存在**（首跑库常见）：该指标写「未记录」并注明「兜底表无流水」，**不得用文件数量反推处理量**。剩余量（如收件箱存量）按目录实际文件数照常计。

## 2. 指标计算（第 1 节）

- **新建原子**：本周仪表盘/迭代日志记为「新建」的原子；文件 mtime 补漏时标「估算」。
- **归并章节**：本周「归并」涉及的老原子与新增章节，列 `[[原子]]`。
- **迭代轮次**：本周迭代日志条数；✅/❌ 从日志结论或仪表盘「结果」列取。
- **晋升**：本周进入 `30-已掌握` 的原子。
- **收件箱**：本周处理 N 条 / 当前剩余 M 条；本周疑问区 +K。无流水时处理量写「未记录」，剩余量照常计。
- **对比上周**：优先读 `_系统/周报/` 中上一份周报的第 1 节；没有则回退仪表盘流水并标「无对比基线」。

---

## 3. 迭代健康度（第 2 节）

### 3.1 待迭代预警 Top5

按 `上次迭代` 升序，取最久未迭代的 5 个 `状态: 迭代中` 原子（含从未迭代的）。输出：概念 | 上次迭代 | 距今天数 | 建议。

### 3.2 停滞清单（**只两类**）

排除 `状态: 已掌握`。判定：

| 类型 | 判定 | 证据 |
| :-- | :-- | :-- |
| **有迭代但无进展** | `迭代次数 >= 1` 且 `上次迭代` 距今 > 7 天 且 `落差值 > 0` | frontmatter 版本/落差值 |
| **刹车** | 最近两条迭代日志结果均为 ❌；或连续两轮 `落差值` 未下降 | 迭代日志 + 当前 frontmatter |

- **新建未跑（迭代次数 = 0）不进本清单**，那属于待迭代预警。
- 每项输出：概念 | 类型 | 停滞天数 | 证据 | 处置建议。
- **处置建议规则**：
  - 落差值高、久未动 → **继续**：排入下周迭代。
  - 连续 ❌ / 落差反复不降 → **拆解**：回拆成更小原子或换重建题。
  - 版本 ≥ v3 仍 ❌ 且无新证据 → **放弃/归档**：移入 `40-素材库` 或标「暂停」，写明理由。

### 3.3 刹车汇总

把 3.2 中「刹车」项单独列一句总结，指出是概念拆分问题还是重建题问题。

---

## 4. 疑问区未解（第 3 节）

- 列出 `疑问/*.md`，排除已在正文标注「已解决」的。
- 输出：问题 | 挂起天数 | 当前判断（一句话）| 建议（本周解决 / 继续挂 / 归档）。
- 挂起 > 30 天且无新信息的，建议归档或删除，征求用户意见。

---

## 5. 项目进展（第 4 节）

- 只列配置未排除、状态不含「已完成 / 已结束 / 暂停」的项目。
- 每个项目：**状态一句话 | 本周变化 | 卡点 | 下一步**（下一步取文档「待办」第一条）。
- **本周变化判定**：有 git 的看 `git -C <项目目录> log --since=<monday> --oneline`；否则看文档与项目目录文件 mtime。无变化写「无进展」。
- **异常提示（必须检查，单列小节）**：
  - 文档「最近更新」> 30 天 → 「文档过期」。
  - 文档声明与事实冲突：如写「收件箱 N 条」而实际为 0、清单状态写「待开始」但考试已结束 → 「文档与事实不符」，并给出应改字段。
  - 项目状态含「已完成」但目录/文档本周仍有改动 → 「已完成但有新动作，确认是否重开」。

---

## 6. 学习计划执行（第 5 节）

按配置逐项：计划 | 来源清单 | 本周完成（新增勾选数）| 累计完成率 | 偏差原因。

- 上周基线：读上一份周报第 5 节；没有则写「首次统计」。
- 计划已结束 / 暂停 → 标「已结束」，不计完成率。
- 配置里计划为空 → 写「暂无进行中计划」。

---

## 7. 本周洞察（第 6 节，2-3 条）

从本周新建 / 归并 / 迭代内容中提炼：

1. **跨领域联系**：至少涉及 2 个不同大类的原子，互相印证或冲突。
2. **本周最值得记住的一条**：带 `[[链接]]`，一句话说清为什么。
3. **一个盲区或反例**：本周暴露的认知缺口、判断失误或没做到的事。

禁止泛泛而谈（「要坚持」「要复盘」这类空话不要写）；每条必须指向具体笔记。

---

## 8. 下周行动（第 7 节）

用 checkbox，控制在 5-7 条：

- [ ] 迭代 3 个优先概念（来自待迭代预警 + 停滞清单，括注理由）
- [ ] 收件箱 / 疑问区处理目标（数量）
- [ ] 每个进行中项目 1 条下一步
- [ ] 学习计划下周目标（按配置）
- [ ] 数据维护（修正过期/不符的交接文档）

---

## 9. 写入与收尾

1. **写周报**：`_系统/周报/<周次>.md`，frontmatter：

```yaml
---
类型: 周报
周次: 2026-W44
周期: 2026-10-26 ~ 2026-11-01
生成: 2026-10-28
一句话: <第 0 节那句话>
---
```

2. **更新索引**：`_系统/周报/_索引.md` 的手动表格顶部加一行（索引不存在则创建）：
   `| 2026-W44 | 10-26 ~ 11-01 | <一句话> | [[2026-W44]] |`

3. **更新仪表盘**：在 `_系统/仪表盘.md`「🕒 最近迭代记录」表顶部加一行：
   `| <日期> | 📊 周报 | — | 已生成 [[2026-W44]]：<一句话> |`
   表或整节不存在时，在仪表盘末尾新建「🕒 最近迭代记录」节（Dataview 查询 + 兜底表）再写入。

4. **汇报给用户**：文件路径、关键数字（新建/归并/迭代/停滞项）、本周最值得做的一件事。

## 11. 配置模板（`_周报配置.md` 不存在时创建）

```markdown
---
类型: 周报配置
更新: {今天}
---

# 周报配置

## 基本设置

| 项 | 值 |
| :-- | :-- |
| 周期 | 周一 ~ 周日（ISO 周） |
| 存放 | `_系统/周报/{ISO年}-W{周号}.md` |
| 报告对象 | 只给自己看 |
| 风格 | 混合式 |

## 学习计划

| 计划 | 来源清单 | 判定方式 | 状态 |
| :-- | :-- | :-- | :-- |

## 项目

- 自动扫描：`_系统/项目交接文档/*.md`
- 排除状态含：`已完成` / `已结束` / `暂停`
- 过期阈值：> 30 天

## 停滞清单口径

- 有迭代但无进展：迭代次数 >= 1，上次迭代 > 7 天，落差值 > 0
- 刹车：最近两条迭代日志 ❌，或连续两轮落差未降
- 新建未跑不进停滞清单
```
