# 知识库问答（Knowledge-Grounded Answering）

> 目标：把知识库当作**你的个人上下文与判断框架**，由模型融合「库内笔记 + 模型推理 + 联网实时信息」，给出一个连贯、可追溯的回答。
> 原则：**库内优先，但不隔离；时效内容必须联网核实；融合回答，来源可追溯。**

## 0. 判定是否走知识库

**走：**
- 知识 / 方法 / 决策 / 诊断 / 对比 / 解释 / 建议类问题
- 用户提到某个概念、笔记、项目、学习进度
- 即使没有说「查知识库」，也默认先查

**不走：**
- 寒暄、闲聊、纯情绪陪伴
- 纯文件操作、代码执行、格式转换
- 用户明确说「不用查库」「直接回答」

不确定时 → **走**（检索成本很低，答偏成本很高）。

## 1. 先分级：这个问题要不要联网

| 级别 | 特征 | 处理 |
| :-- | :-- | :-- |
| **A 稳定知识** | 心理机制、人际关系、学习方法、逻辑/数学、编程原理 | 库内 + 模型融合，不必联网 |
| **B 时效知识** | 平台政策、GitHub 项目、API/版本/价格、法规、榜单、新闻、「最新/现在/今年」 | **必须联网核实**后再答 |
| **C 混合问题** | 用库内框架分析一个会变的外部对象（如「用库里的方法做增长」） | 库内框架 + 联网事实 |

**触发联网的信号（命中任一即搜）：**
- 时间词：现在 / 目前 / 最新 / 今年 / 最近 / 具体年份（如「2025」「今年」）/ 还有效吗
- 外部对象：微信小程序、抖音、小红书、支付宝、App Store 等**平台规则/政策/审核**
- 代码与工具：GitHub 仓库、开源项目、依赖库、SDK/API 的**用法、版本、限额、定价、是否维护**
- 现实事实：法律法规、补贴政策、硬件价格、赛事/榜单、公司动态
- 库内笔记**依赖外部事实**（政策、版本、价格、链接），且用户要拿它做当下决策
- 你内心不确定「这个事实会不会已经变了」→ **搜**（漏搜的代价远大于多搜一次）

> 笔记 frontmatter 的 `上次迭代` 只作辅助信号：超过 6 个月且内容依赖外部事实 → 重点核实。稳定知识不会因为笔记旧就失效。

## 2. 检索知识库（最多 3 轮，最多读 5 个文件）

### 第 1 轮：概念名直查（最快）
把问题拆成 2–5 个关键词 + 同义词，先按**概念文件夹名**找：

```bash
ls "{{VAULT_PATH}}/10-知识原子"
# 扁平库（<概念>/）在第 1 层，分类库（<大类>/<概念>/）在第 2 层，一条命令同时覆盖
find "{{VAULT_PATH}}/10-知识原子" "{{VAULT_PATH}}/30-已掌握" -mindepth 1 -maxdepth 2 -type d
```

> 判定概念文件夹：**直接包含 `<概念名>.md`（四件套）的那一层**；分类库的第 1 层是大类，忽略即可。

或用 Glob：`10-知识原子/**/*关键词*.md`、`30-已掌握/**/*关键词*.md`。

### 第 2 轮：全文检索
概念名没命中，再搜正文与 frontmatter（领域 / 上位概念 / 前置依赖）：

```
Grep pattern="关键词1|关键词2|同义词" path="10-知识原子" glob="*.md" output_mode="files_with_matches"
Grep pattern="..." path="30-已掌握" ...
Grep pattern="..." path="40-素材库" ...
Grep pattern="..." path="疑问" ...
```

（以上路径相对 vault 根目录。）先用 `files_with_matches` 缩小范围，**不要直接读全部命中文件**。

### 第 3 轮：一跳扩展（可选）
只沿**直接相关**的 `上位概念` / `前置依赖` / `关联产物` wikilink 扩展 1 跳，不做全图遍历。

### 读取优先级
1. `压缩版.md` — 最快建立准确理解
2. `<概念名>.md` — 核心机制、边界、落差记录
3. `教授稿.md` — 需要类比/向新手解释时
4. `重建稿.md` — 用户问「怎么从零推出来」时
5. `30-已掌握/` — 可信度高于迭代中
6. `40-素材库/` — 原子不够时才读，引用时说明是「素材」
7. `疑问/` — 说明尚未解决，不当结论

**不要默认打开 `_系统/仪表盘.md`**（很大）。问进度/队列时用 Grep 定位相关行再读。

## 3. 联网检索（B/C 级问题必做）

### 搜索顺序
1. **WebSearch**：查询词带「对象 + 年份 + 官方关键词」，如 `微信小程序 审核政策 2026 官方`、`项目名 GitHub releases`、`API pricing 2026`。必要时中英文各搜一次。
2. **WebFetch 一手来源**：
   - 官方文档 / 开放社区 / 政府或监管网站
   - GitHub：优先 `gh repo view`、`gh release list`、`gh api`；或直接抓 README / releases / issues
   - 官方定价页、changelog、release notes
3. **交叉验证**：政策、价格、限额、版本号这类硬事实，尽量用 2 个来源确认；记录发布日期/更新时间。
4. **失败处理**：搜不到或打不开 → 明确说「未能联网核实」，并把相关结论标为**可能过时**，不要假装查过。

### 来源优先级
官方文档 / 仓库本体 > 官方公告 / changelog > 主流技术媒体 > 博客 / 论坛 / 二手教程。
内容农场、聚合站、无日期文章 → 不作为关键事实依据。

### 预算
1–3 次搜索、1–3 次抓取。够用即停，不要为了「显得全面」堆来源。

## 4. 融合回答（核心）

**不要**把回答拆成「库内依据 / 库外补充」两大块。库内笔记是**骨架和判断框架**，模型负责推理与补全，联网事实负责校准当下。

### 推荐结构
```
**结论**：1–3 句直接回答。

**展开**：把库内框架、模型推理、联网事实揉成连贯叙述。
- 引用库内概念时内联 [[概念名]]，不要机械摘抄。
- 引用会变的事实时就近给来源与日期，如（[官方文档](url)，{核实日期}）。

**时效与边界**：哪些结论可能随时间变化、最后核实日期、库内笔记是否需要更新。

**下一步**（可选）：具体动作；值得沉淀的缺口建议入收件箱。
```

### 融合规则
- **以库内为个人视角**：用户问自己的理解、选择、习惯时，库内笔记的权重高于通用模型知识。
- **以联网为外部事实**：用户问平台规则、项目现状、版本/价格时，最新官方来源的权重高于库内旧笔记和模型记忆。
- **模型负责连接**：把库内概念与外部事实接起来解释「为什么」「所以对你意味着什么」，而不是并列罗列。
- **允许自然引用**：同一段话里可以同时出现 `[[概念]]` 和网页来源，不必分区。
- **不确定就标注**：推论写「按笔记推导」，未核实写「未联网核实，可能过时」。

### 引用规则
- 库内：只引用**真正读过**的文件，用相对 wikilink `[[概念名]]`。
- 联网：给可点击来源 + 日期；**禁止编造 URL、标题、版本号、政策条款**。
- 一次回答聚焦 3–5 个核心概念，来源按需给，不做文献综述。

## 5. 冲突与过时处理

| 冲突类型 | 处理 |
| :-- | :-- |
| 库内 vs 联网（政策/版本/价格） | 以**最新官方来源**为准；说明库内哪条已过时，建议「迭代 [[概念]]」更新 |
| 库内 vs 模型知识 | 个人框架类以库内为主；外部事实类看是否已联网核实 |
| 库内笔记之间冲突 | 按 `30-已掌握` > 迭代中 > 素材库 排序，指出冲突并建议跑一轮迭代 |
| 笔记标了「作者观点」 | 保持标注，不升级为事实 |
| 联网来源互相冲突 | 优先官方/更新时间更近的；明确说明分歧 |

**永远不要静默覆盖库内结论**：指出差异即可，改笔记走「知识迭代」。

## 6. 检索不到时

1. 明确说：**「知识库未覆盖『X』」**（联网结果另算）
2. 用模型知识 + 联网结果回答，标注来源
3. 值得沉淀的概念 → 建议丢进 `00-收件箱`，或说「整理收件箱」建四件套
4. 已有概念的盲区 → 建议「迭代 [[概念]]」把这次落差补进去

## 7. 常见时效对象速查

| 对象 | 首选来源 |
| :-- | :-- |
| 微信小程序 / 公众号政策 | 微信开放文档、微信开放社区公告 |
| 抖音 / 小红书 / 电商规则 | 对应开放平台/规则中心官方页 |
| GitHub / 开源项目 | 仓库 README、releases、issues、commit 记录 |
| AI API / SDK | 官方 docs、pricing、changelog、模型卡 |
| 软件 / 框架版本 | 官方 release notes、迁移指南 |
| 法规 / 补贴 / 资质 | 政府、监管部门官网 |
| 硬件 / 商品价格 | 官方商城、主流电商当前页 |

## 8. 红线

- **不读不引**：没打开文件就给 wikilink = 违规。
- **时效内容不联网就断言** = 违规（政策、版本、价格、项目现状）。
- **不编造来源**：URL、标题、日期、版本号、条款都不能凭空写。
- **不假装查过**：联网失败要明说。
- **不混成无法追溯的一锅粥**：融合可以，但关键事实要能指出「来自库内 / 来自模型 / 来自哪个网页」。
- **不擅自改笔记**：问答只读；更新走「知识迭代」，归类走「整理收件箱」。
- **不喧宾夺主**：回答以解决问题为主，引用是支撑。
- 用户说「不用查库 / 不用联网」→ 立即遵从。

## 9. 收尾一行（可选）

复杂回答末尾加一行状态：
`依据：[[A]]、[官方文档](url)（{核实日期}）｜ 时效风险：中 ｜ 库内待更新：X`
